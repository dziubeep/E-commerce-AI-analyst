Phase 1: The Data Foundation & "Ground Truth" (Weeks 1-2)
The Argument: An AI cannot generate correct SQL if you, the developer, don't know what correct SQL looks like for your dataset.

Task 1: Download the "Online Retail II" dataset from Kaggle.

Task 2: Run the etl.py script to clean the data (handle missing IDs, remove cancellations) and load it into a local ecom.db SQLite database.

Task 3: Create your business_logic.txt file. You must manually write 5-10 "Gold Standard" questions and their perfect SQL answers. (e.g., Question: "What was the revenue last month?" -> Answer: "SELECT SUM(Quantity * Price) FROM transactions WHERE..."). This becomes the core of your AI's brain.

Phase 2: The Generation & Context Core (Weeks 3-4)
The Argument: Bare LLMs hallucinate column names. Injecting context prevents this.

Task 1: Set up your Gemini API connection in Python.

Task 2: Build the Prompt Template. It must clearly state the persona ("You are an expert Data Analyst"), inject the database schema, and inject the 5 "Gold Standard" examples from your text file.

Task 3: Write the basic execution function: User asks question -> AI generates SQL -> Python runs pandas.read_sql() -> Print result.

Phase 3: The "Self-Healing" Execution Loop (Week 5)
The Argument: This is your competitive advantage. Systems that crash lose trust instantly. Systems that silently fix their own errors look like magic.

Task 1: Wrap your execution function in a try...except block.

Task 2: If pandas.read_sql() throws an error, capture the exact SQLite error string.

Task 3: Programmatically append this string to the chat history: "The query failed with error: [Error]. Rewrite the SQL." and send it back to the AI. Limit this loop to 3 attempts to save API costs.

Phase 4: The Explainability & Trust Layer (Week 6)
The Argument: Business owners will not make financial decisions based on a black-box number. They need to know the assumptions the AI made.

Task 1: Add a strict instruction to your prompt: "After generating the SQL, provide a 1-2 sentence explanation of the logic used, starting with 'I calculated this by...'"

Task 2: Ensure your Python script separates the SQL code, the Data output, and the text Explanation, returning all three cleanly.

Phase 5: Interface, Memory, and Guardrails (Week 7)
The Argument: The user experience must be seamless and focused exclusively on business data.

Task 1: Build the UI using Streamlit. Create a chat-like interface.

Task 2: Implement Conversational Memory. If a user asks "What about November?", the system must remember the previous question was about revenue.

Task 3: Build a lightweight "Guardrail" prompt that runs before the SQL generation to check if the user is asking a non-data question (e.g., "Write me a poem"). If yes, politely decline.

Phase 6: Beta Launch & Polish (Week 8)
The Argument: A project is just a hobby until someone else uses it.

Task 1: Deploy the app for free using Streamlit Community Cloud or Render.

Task 2: Conduct "Red Teaming." Try to break your own app by asking weird, ambiguous, or poorly spelled questions.

Task 3: Find 2-3 local e-commerce owners to test it. Watch them use it without helping them. Where they get confused is exactly what you need to fix for V1.1.
